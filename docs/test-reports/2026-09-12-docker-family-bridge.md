# Отчёт тестового Docker-прогона семейного MAX ↔ Telegram bridge

> **Дата:** 2026-09-12
> **Назначение:** зафиксировать исходный и кандидатный прогоны в изолированном тестовом окружении

## Проверенные версии

- Исходная версия: `33494cb`.
- Кандидат: `5db6a2b` — «Исправить типы реакций в очереди»; включает `373499a`.
- Ветка локальной копии: `dev`.

Для исходной версии использованы только два файла тестового контура из кандидатной версии (`deploy/Dockerfile.test` и `deploy/docker-compose.test.yml`): в исходном коммите этот тестовый контур ещё отсутствовал. Исходный код при этом не изменялся.

## Окружение сервера

- ОС: Ubuntu 22.04.5 LTS.
- Docker: 29.1.3.
- Docker Compose: 2.40.3.
- Ресурсы сервера: 2 CPU, 3.8 ГБ RAM, без swap.

## Изоляция теста

Тесты запускались в отдельных Compose-проектах:

- `maxgram-test-baseline-20260912`;
- `maxgram-test-candidate-20260912`.

Контейнер тестов имеет следующие ограничения:

- сеть отключена (`network_mode: none`);
- тома с хоста не подключаются;
- корневая файловая система только для чтения;
- временная область — отдельный `tmpfs` без выполнения файлов;
- удалены все Linux-возможности (`cap_drop: ALL`);
- включён запрет повышения прав;
- пользователь контейнера — непривилегированный `tester`;
- лимиты: 1 CPU, 768 МБ RAM, 128 процессов;
- используются только фиктивные значения конфигурации, без реальных токенов, MAX-сессии и аккаунтов.

В образе кандидатной версии Python `3.13.15`, рабочая папка `/app`, пользователь по умолчанию `tester`.

## Результаты

Команда в обоих случаях:

```text
docker compose -p <проект> -f deploy/docker-compose.test.yml run --rm tests
```

- Исходная версия `33494cb`: **449 passed**, 4 предупреждения, 13.54 с.
- Кандидат `5db6a2b`: **461 passed**, 4 предупреждения, 12.56 с.

Предупреждения — это сообщения Hypothesis и pytest о невозможности создать кэш в `/app`, потому что файловая система контейнера намеренно только для чтения. На прохождение тестов они не повлияли.

После прогона read-only проверка списка Docker-контейнеров показала только ранее существовавшие сервисы: `hermes-browser`, `hermes`, `dazzling_meitner`, `angry_hoover`. Они не изменялись.

## Статические проверки кандидата

- Ruff: **пройден** (`All checks passed!`).
- Проверка синтаксиса Python через `compileall`: **пройдена**; служебный байткод направлялся только во временную область контейнера.
- Mypy для изменённых модулей: новых ошибок не добавлено. В кандидатной и исходной версиях остаются одинаковые 17 ошибок в старых участках Telegram-адаптера и композиции приложения.
- Полный запуск mypy по проекту: 271 ошибка в 28 файлах; это существующий технический долг, не блокирующий текущий тестовый прогон.

## Границы этого этапа

Реальные Telegram/MAX-аккаунты, настоящие токены, постоянный запуск моста, firewall и общие настройки Docker не подключались и не менялись.
